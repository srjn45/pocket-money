## 2. Backend: embed the web dist with SPA fallback

Create package `backend/internal/web`:

- **`backend/internal/web/embed.go`** — the embed + the SPA handler. Sketch:

  ```go
  package web

  import (
      "embed"
      "io/fs"
      "net/http"
      "strings"

      "github.com/gin-gonic/gin"
  )

  //go:embed all:dist
  var dist embed.FS

  // RegisterSPA serves the embedded expo-web build and falls back to index.html
  // for client-side routes. It MUST be called AFTER all /api and /health routes
  // are registered, so it only catches unmatched paths (gin NoRoute).
  func RegisterSPA(r *gin.Engine) error {
      sub, err := fs.Sub(dist, "dist")
      if err != nil {
          return err
      }
      fileServer := http.FileServer(http.FS(sub))
      index, err := fs.ReadFile(sub, "index.html")
      if err != nil {
          return err // embed misconfigured — fail loudly at boot, never silently 404
      }

      r.NoRoute(func(c *gin.Context) {
          p := c.Request.URL.Path
          // NEVER shadow the API or health surface. Unmatched /api/... (e.g. a
          // typo'd endpoint) must 404 as JSON, not return the SPA shell.
          if strings.HasPrefix(p, "/api/") || p == "/health" {
              c.JSON(http.StatusNotFound, gin.H{"error": "not found"})
              return
          }
          // Serve a real asset if it exists; otherwise hand back index.html so
          // deep links like /groups/123 / /invite?token=… boot the SPA.
          if _, statErr := fs.Stat(sub, strings.TrimPrefix(p, "/")); statErr == nil && p != "/" {
              fileServer.ServeHTTP(c.Writer, c.Request)
              return
          }
          c.Data(http.StatusOK, "text/html; charset=utf-8", index)
      })
      return nil
  }
  ```

  Implementer notes:
  - `//go:embed all:dist` uses the `all:` prefix so dot/underscore files (expo emits `_expo/…`)
    are included.
  - The existence probe (`fs.Stat`) is what lets hashed assets (`/_expo/...`, `/assets/...`,
    `/favicon.ico`) serve as files while unknown paths return the SPA shell. Cache headers are
    out of scope for this WP.
  - `RegisterSPA` returns an error; `main` must `log.Fatalf` on it so a broken embed can never
    boot into a silent 404 farm.

- **`backend/internal/web/dist/index.html`** — a **committed stub** so the package compiles when
  no export is present (local `go build`/`vet`/`test`, and the CI `lint`/`test`/`build`-of-binary
  steps that do not run the web export). `//go:embed all:dist` fails to compile if the directory
  has no matching files, so a real committed file is required. Stub body: a minimal
  `<!doctype html><title>pocket-money</title>` placeholder. The Docker build **overwrites** this
  directory with the real export before `go build` (§4, stage 2).

- **`.gitignore`** — ignore the exported dist but keep the stub:

  ```gitignore
  /backend/internal/web/dist/*
  !/backend/internal/web/dist/index.html
  ```

  (Root `.gitignore` — path is repo-relative.)

- **`backend/cmd/server/main.go`** — after all routes are registered (after line 126, i.e. after
  the `/api/v1` group and `/health`), before `router.Run`:

  ```go
  if err := web.RegisterSPA(router); err != nil {
      log.Fatalf("Failed to register web SPA: %v", err)
  }
  ```

  Add the import `"github.com/srjn45/pocket-money/backend/internal/web"`. Leave CORS and all
  existing routes untouched.

**Ordering invariant (critical):** `/health` and `/api/v1/*` are registered on the engine as
concrete routes, so gin matches them first and `NoRoute` never fires for them. The `strings.HasPrefix(p, "/api/")`
guard is the belt-and-suspenders for *unregistered* `/api/...` paths. Verify both:
`GET /api/v1/nope` → JSON 404 (not HTML), `GET /health` → the health JSON, `GET /groups/x` → HTML shell.

## 4. Root multi-stage Dockerfile

Create **`Dockerfile` at the repo root** (build context = repo root, so the go build can see the
web export copied out of stage 1). Three stages:

```dockerfile
# ── Stage 1: export the Expo web bundle ───────────────────────────────
FROM node:22-alpine AS web
WORKDIR /app
# Deps first for layer caching.
COPY app/package.json app/package-lock.json ./
RUN npm ci
COPY app/ ./
# RELATIVE api base → same-origin, CORS moot. Baked into the JS bundle at export.
ENV EXPO_PUBLIC_API_URL=/api/v1
ENV NODE_ENV=production
RUN npx expo export --platform web
# Output: /app/dist  (index.html + _expo/… + assets/…)

# ── Stage 2: build the Go binary with embedded dist + migrations ──────
FROM golang:1.24-alpine AS build
RUN apk add --no-cache git
WORKDIR /src
COPY backend/go.mod backend/go.sum ./
RUN go mod download
COPY backend/ ./
# Drop the real web export on top of the committed stub, then embed it.
RUN rm -rf internal/web/dist
COPY --from=web /app/dist ./internal/web/dist
RUN CGO_ENABLED=0 GOOS=linux go build -ldflags="-w -s" -o /server ./cmd/server

# ── Stage 3: slim runtime ─────────────────────────────────────────────
FROM alpine:3.19
RUN apk --no-cache add ca-certificates tzdata wget
WORKDIR /app
COPY --from=build /server .
RUN adduser -D -g '' appuser
USER appuser
EXPOSE 8080
HEALTHCHECK --interval=30s --timeout=3s --start-period=10s --retries=3 \
    CMD wget --no-verbose --tries=1 --spider http://localhost:8080/health || exit 1
CMD ["./server"]
```

Key points / gotchas the implementer must get right:
- **Context is the repo root** — every `COPY` is repo-relative (`app/...`, `backend/...`). The
  build must run from the root (`docker build .` / compose `context: .`), **not** `./backend`.
- **`COPY --from=web /app/dist ./internal/web/dist`** lands the export exactly where
  `//go:embed all:dist` (in `backend/internal/web/embed.go`, whose package dir is
  `/src/internal/web`) looks. The `rm -rf internal/web/dist` first removes the committed stub so
  the stub `index.html` can't shadow the real one.
- **No migrations copy, no dist copy in stage 3** — both are embedded in `/server`. The runtime is
  a single static binary + certs. `wget` is added for the healthcheck (busybox `wget` in alpine).
- No build args are required. (`EXPO_PUBLIC_API_URL` is a stage-1 `ENV`, fixed to `/api/v1`; do
  **not** parametrise it — a same-origin single image is the whole point.)
- **Delete `backend/Dockerfile`** (superseded). Check `backend/docker-compose.test.yml` — if it
  `build:`s `backend/Dockerfile`, repoint or leave it (it's the integration-test DB compose; likely
  postgres-only). Verify before deleting.

## 5. docker-compose.yml — postgres + app (single image)

Rewrite the root `docker-compose.yml` to two services. **One** required secret: `JWT_SECRET`.

```yaml
services:
  postgres:
    image: postgres:15-alpine
    container_name: pocket_money_db
    ports:
      - "5432:5432"            # exposed so CI seed (host go-run) can reach it
    environment:
      POSTGRES_USER: pocket
      POSTGRES_PASSWORD: pocket
      POSTGRES_DB: pocket_money
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U pocket -d pocket_money"]
      interval: 5s
      timeout: 5s
      retries: 5

  app:
    build:
      context: .
      dockerfile: Dockerfile
    container_name: pocket_money_app
    ports:
      - "8080:8080"
    environment:
      DATABASE_URL: postgres://pocket:pocket@postgres:5432/pocket_money?sslmode=disable
      JWT_SECRET: ${JWT_SECRET:?JWT_SECRET must be set}
      # PORT defaults to 8080; CORS_ORIGINS unneeded (same origin);
      # APP_BASE_URL unset → invites default to the request host (§1).
    depends_on:
      postgres:
        condition: service_healthy
    healthcheck:
      test: ["CMD", "wget", "--no-verbose", "--tries=1", "--spider", "http://localhost:8080/health"]
      interval: 10s
      timeout: 3s
      retries: 5
      start_period: 15s
    restart: unless-stopped

volumes:
  postgres_data:
```

- `${JWT_SECRET:?…}` makes `JWT_SECRET` the single mandatory input — `docker compose up` fails fast
  with a clear message if it's missing. README documents `JWT_SECRET=... docker compose up` (or an
  `.env`).
- Networks block can be dropped (compose default bridge suffices); keep only if `backup-verify`
  depends on a named network (it doesn't).
- **`backup-verify` CI job** currently does `docker compose up -d postgres` + `make backup`. That
  still works (postgres service unchanged) — verify it isn't broken by the removal of the `backend`
  service or `CORS_ORIGINS`.

## 6. e2e wiring for the single-image origin

The suite is already parametrised by `E2E_WEB_BASE` / `E2E_API_BASE`. For the single image both
point at `http://localhost:8080` (web served at `/`, API at `/api/v1`, same origin). The **only**
code change is the Playwright `webServer` block, which currently spins up `npx serve` for the
dev-server path and must be **skipped** when an external server (the single image) is already up.

- **`e2e/playwright.config.ts`** — gate `webServer` behind an env flag:

  ```ts
  const useExternalServer = !!process.env.E2E_EXTERNAL_SERVER;
  export default defineConfig({
    // …
    use: { baseURL: process.env.E2E_WEB_BASE ?? 'http://localhost:8081', /* … */ },
    // …
    webServer: useExternalServer ? undefined : {
      command: 'npx serve -s ../app/dist -l 8081',
      url: 'http://localhost:8081',
      reuseExistingServer: !process.env.CI,
      timeout: 120_000,
    },
  });
  ```

  With `E2E_EXTERNAL_SERVER=1`, Playwright starts no server and drives the running single image.
- No change needed to `e2e/support/api.ts` (reads `E2E_API_BASE`), `e2e/support/pages.ts`
  (full-URL nav via `baseURL`), or `e2e/tests/seeded-readonly.spec.ts` (reads `E2E_WEB_BASE` and
  self-skips without `seed.summary.json`).
- The seed step still writes `e2e/fixtures/seed.summary.json` so `seeded-readonly` runs (parity
  with today's `e2e` job).

## 7. CI — replace the dev-server E2E with a compose smoke

Edit `.github/workflows/ci.yml`:

1. **`build` job** — replace the `docker build -t pocket-money-backend ./backend` step (which built
   the old backend-only image from `./backend`) with a **root image build** to prove the multi-stage
   Dockerfile compiles:
   ```yaml
   - name: Build single-image
     run: docker build -t pocket-money:${{ github.sha }} .
   ```
   Keep the `go build` binary step (fast signal) or fold it in — either is fine; the root image
   build is the new authority. Drop the `working-directory: ./backend` default for that step.

2. **Remove the existing `e2e` job** (the `go run ./cmd/server` + `npx serve` dev-server path) and
   **add `compose-smoke`** in its place. It boots the single image via compose and runs the
   existing suite against it:

   ```yaml
   compose-smoke:
     name: Compose Smoke (single-image e2e)
     runs-on: ubuntu-latest
     needs: [lint, test]                # gate the smoke behind the cheap floors
     env:
       TZ: UTC
       E2E_WEB_BASE: http://localhost:8080
       E2E_API_BASE: http://localhost:8080/api/v1
       E2E_EXTERNAL_SERVER: "1"         # single image serves the web; no npx serve
     steps:
       - uses: actions/checkout@v4

       - name: Setup Go            # for the host-run seed
         uses: actions/setup-go@v5
         with: { go-version: '1.24', cache-dependency-path: backend/go.sum }
       - name: Setup Node          # for e2e deps + playwright
         uses: actions/setup-node@v4
         with: { node-version: '22', cache: 'npm', cache-dependency-path: e2e/package-lock.json }

       - name: Build + boot single image
         env:
           JWT_SECRET: ci-smoke-secret
         run: docker compose up -d --build

       - name: Wait for app health
         run: |
           for i in $(seq 1 60); do
             curl -sf http://localhost:8080/health && echo "app ready" && exit 0
             echo "waiting for app... ($i)"; sleep 3
           done
           echo "app never became healthy" >&2
           docker compose logs app
           exit 1

       - name: Seed demo family (host go-run → exposed postgres)
         working-directory: ./backend
         env:
           DATABASE_URL: postgres://pocket:pocket@localhost:5432/pocket_money?sslmode=disable
           JWT_SECRET: ci-smoke-secret
           # APP_BASE_URL intentionally unset → invites use request host (same origin)
         run: go run ./cmd/seed --reset --out ../e2e/fixtures/seed.summary.json

       - name: Install e2e deps
         working-directory: ./e2e
         run: npm ci
       - name: Install Playwright chromium
         working-directory: ./e2e
         run: npx playwright install --with-deps chromium
       - name: Run e2e against single image
         working-directory: ./e2e
         run: npx playwright test

       - name: App logs on failure
         if: failure()
         run: docker compose logs app
       - name: Upload Playwright report on failure
         if: failure()
         uses: actions/upload-artifact@v4
         with: { name: playwright-report, path: e2e/playwright-report/, retention-days: 7 }
       - name: Tear down
         if: always()
         run: docker compose down -v
   ```

Design decisions baked in above (call them out in the PR body):
- **compose-smoke *replaces* the dev-server `e2e` job.** The plan requires the suite to run against
  the single image, "not the dev servers" — running both would be redundant and slower. Delete the
  old job; `compose-smoke` is the e2e gate.
- **The app container runs migrations on boot** (via the embedded iofs source). The seed runs
  *after* `/health` is green, so the schema exists. Postgres 5432 is exposed so the host `go run`
  seed can reach it (same pattern the current `e2e` job uses for its services-postgres).
- **Same-origin, no CORS, relative API** — the web bundle baked into the image was exported with
  `EXPO_PUBLIC_API_URL=/api/v1`, so the browser calls `http://localhost:8080/api/v1/...` (page
  origin). `E2E_API_BASE` for the test *helpers* (`e2e/support/api.ts`) is the absolute
  `http://localhost:8080/api/v1`.
- `needs: [lint, test]` keeps the expensive Docker job behind the cheap Go floors. `fe-web-export`
  stays as-is (fast FE bundle floor per §9.3) and is independent.
- **Concurrency note:** the root `docker build` re-runs `npm ci` + `expo export` inside stage 1, so
  the image build is the slow step. Acceptable; leave build caching to a follow-up if needed.

   compile. `all:` prefix is required for expo's `_expo/` dot/underscore files.
