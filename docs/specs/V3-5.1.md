## 0. Summary

Turn the **insert-only** notifications table (created in V3-2.1, migration 014) into a
read/mark API scoped strictly to the caller's own `user_id`, and add the **N-3
`payment_recorded`** insert at the settlement (clearing) posting site, atomic with the
ledger row. No migration (table + index already exist). No FE work (that is V3-5.2).

Nothing here changes auth or money semantics beyond what D1–D9 already settle; the one
new behavioural decision (skip self-notification) is stated in §4 and mirrors the existing
N-2 precedent — **no open question requires the brain** (see §9).

## 1. Endpoints

All four are **authed** (`BearerAuth`, registered under the `protected` group) and
**scoped to the caller's own `user_id`** taken from the JWT — a user can only ever
see/mark their own notifications. There is no group in the path: notifications belong to
users, not groups.

| # | Method & path | Purpose | Success | Error codes |
|---|---|---|---|---|
| E1 | `GET /api/v1/notifications?limit=&cursor=` | Paged list, newest first | `200` `NotificationListResponse` | `400` bad limit/cursor, `401` |
| E2 | `GET /api/v1/notifications/unread_count` | Unread badge count | `200` `UnreadCountResponse` | `401` |
| E3 | `POST /api/v1/notifications/{id}/read` | Mark one read (idempotent, ownership-checked) | `204` No Content | `400` bad id, `401`, `404` not the caller's / nonexistent |
| E4 | `POST /api/v1/notifications/read_all` | Mark all caller's unread read | `200` `MarkAllReadResponse` | `401` |

Notes binding on the implementer:

- **404, not 403, for E3 on a foreign/absent id.** Returning 403 would leak that the id
  exists. The `WHERE id=$1 AND user_id=$2` filter makes "not yours" and "doesn't exist"
  indistinguishable — both → 404. (Consistent with not leaking existence; §9.5 authz.)
- **E3 is idempotent**: marking an already-read notification succeeds `204` and does
  **not** move `read_at` (see `MarkRead` SQL, §2). Only a genuinely foreign/absent id 404s.
- No `500`-on-empty: an empty list is `200 {"items":[],"next_cursor":null}`, count `0`.
- Standard `ErrorResponse {error}` envelope on every non-2xx (house style, §9).

### 1.1 Pagination scheme — keyset cursor on `(created_at, id)`, newest first

Chosen over offset paging: stable under concurrent inserts (a new N-3 arriving mid-scroll
never shifts a page), and the existing index `idx_notifications_user_created
(user_id, created_at DESC)` already serves it. `id` is the tiebreaker for rows sharing a
`created_at` (same-tx inserts).

- `limit`: optional, default **20**, clamp to **[1, 100]**; out-of-range or non-integer → `400`.
- `cursor`: optional opaque string. **First page** omits it. It is base64url(no-pad) of
  `"<RFC3339Nano created_at>|<uuid id>"` — the `created_at`+`id` of the **last item of the
  previous page**. Malformed/undecodable cursor → `400` (do not silently treat as first page).
- Query: fetch `limit+1` rows

  ```sql
  SELECT id, user_id, type, payload, read_at, created_at
  FROM notifications
  WHERE user_id = $1
    AND ( $2::timestamptz IS NULL
          OR (created_at, id) < ($2::timestamptz, $3::uuid) )
  ORDER BY created_at DESC, id DESC
  LIMIT $4;              -- $4 = limit+1
  ```

  If `limit+1` rows come back, drop the extra and set `next_cursor` from the **last kept**
  row; otherwise `next_cursor = null` (last page). `$2/$3` are NULL on the first page.

### 1.2 Response JSON

```jsonc
// E1  NotificationListResponse
{
  "items": [
    {
      "id": "…uuid…",
      "type": "payment_recorded",            // added_to_group | shadow_claimed | payment_recorded
      "payload": { "group_id": "…", "amount": { "currency": "INR", "value": 40000 } },
      "read_at": null,                        // RFC3339 timestamp or null
      "created_at": "2026-07-11T09:00:00Z"
    }
  ],
  "next_cursor": "MjAyNi0wNy0xMVQwOTowMDowMFp8…"   // opaque; null on last page
}
// E2  { "count": 3 }
// E4  { "updated": 3 }
// E3  204 No Content (empty body)
```

`payload` is passed through verbatim as the stored JSONB object (free-form — each `type`
carries its own shape; the FE switches on `type`). It is **not** re-validated or reshaped
by the read API. See §4 for the N-3 payload shape the write side now produces.

## 2. Repo methods — `backend/internal/db/notification_repo.go`

Add READ methods alongside the existing `Insert`. All filter by `user_id`. Add a
`Notification` model first (see §6). Suggested signatures:

```go
// List returns up to `limit` of userID's notifications, newest first, keyset-paged.
// afterCreatedAt/afterID are the previous page's last row (both nil on the first page).
// Caller passes limit+1 is NOT expected here — pass the page size; the handler asks for
// limit+1 by incrementing before the call, OR List fetches limit+1 internally and returns
// a bool hasMore. Pick one and keep it consistent; recommendation: List(ctx, userID, limit)
// fetches limit+1 and returns (items []*models.Notification, hasMore bool, err error).
func (r *NotificationRepo) List(ctx context.Context, userID uuid.UUID, limit int,
    afterCreatedAt *time.Time, afterID *uuid.UUID) (items []*models.Notification, hasMore bool, err error)

// UnreadCount returns the number of unread (read_at IS NULL) notifications for userID.
func (r *NotificationRepo) UnreadCount(ctx context.Context, userID uuid.UUID) (int, error)

// MarkRead marks notification id read for userID. Idempotent (already-read stays put),
// ownership-checked. Returns found=false when the id is absent OR not userID's → handler 404s.
func (r *NotificationRepo) MarkRead(ctx context.Context, id, userID uuid.UUID) (found bool, err error)

// MarkAllRead marks every unread notification for userID read; returns rows affected.
func (r *NotificationRepo) MarkAllRead(ctx context.Context, userID uuid.UUID) (int64, error)
```

SQL:

- **List** — the §1.1 query. `hasMore = len(rows) > limit`; trim to `limit`.
- **UnreadCount** — `SELECT count(*) FROM notifications WHERE user_id=$1 AND read_at IS NULL`.
- **MarkRead** — one statement does ownership + idempotency:

  ```sql
  UPDATE notifications
  SET read_at = COALESCE(read_at, now())     -- idempotent: don't move an existing read_at
  WHERE id = $1 AND user_id = $2
  RETURNING id;                              -- 0 rows ⇒ found=false ⇒ handler 404
  ```

  `found = (rows returned == 1)`. Never a plain "not found" vs "forbidden" split — one 404.
- **MarkAllRead** —
  `UPDATE notifications SET read_at = now() WHERE user_id=$1 AND read_at IS NULL`,
  return `CommandTag.RowsAffected()`.

The methods run on `r.pool` (no tx needed — each is a single statement). Keep the existing
`Insert(ctx, q Querier, …)` tx-joining signature untouched; the write path (§4) still uses it.

## 4. N-3 insert — `payment_recorded`

### 4.1 Where

The "record payment" screen (V3-4.2) posts a **settlement** (clearing, D9 "payment") via
`POST /groups/:id/ledger` with `entry_type=settlement`, handled by
**`LedgerHandler.CreateLedger`** in `backend/internal/handlers/ledger.go`. The settlement
branch is `case models.EntryTypeSettlement:` (**`ledger.go:362`**); the single shared row
insert for all entry types is `h.ledgerRepo.Create(...)` at **`ledger.go:422`**. That
insert is where N-3 must become atomic with the ledger row — **call-site: `ledger.go:422`**
(within the settlement path only).

### 4.2 Recipient and the self-payment rule

- **Recipient = `targetUserID`** — the member the clearing is recorded *for* (the payee),
  computed by `resolveTargetUser` in the settlement branch. This is the member whose
  balance the payment clears. Actor = `userID` (the admin; only admins may post settlements).
- **Rule (explicit, per plan intent "to member when a clearing is recorded for them"):**
  insert N-3 to `targetUserID`, **except** skip when `targetUserID == userID` (an admin who
  is also a member recording a payment to themselves is not notified). This mirrors the N-2
  precedent (`auth.go:212`, `if adminID == locked.ID { continue }`). State it in a code
  comment referencing that precedent.
- N-3 fires **only** for `entry_type=settlement` — never for chore/adjustment. Adjustments
  are explicitly out of scope (§3.7 lists only clearings for N-3).

### 4.3 Payload

```jsonc
{
  "group_id":   "<uuid>",
  "group_name": "<string>",                     // for a self-contained bell line, like N-1/N-2
  "amount":     { "currency": "INR", "value": 40000 }   // Money; minor units, group currency (D7)
}
```

`amount.value` = the settlement `amount` (minor units, already validated `> 0` and
currency-matched to the group at `ledger.go:293`/`:372`). `currency` = the group's
`currency` already in scope in the handler. Marshal with `json.Marshal` (house style,
`auth.go:200`). Add the type constant to `models`:

```go
NotificationPaymentRecorded = "payment_recorded" // N-3
```

### 4.4 Atomicity — make the settlement insert transactional

`LedgerRepo.Create` currently runs on `r.pool` directly (`ledger_repo.go:74`) and is called
positionally by ~10 integration tests — **do not change its signature.** Instead:

1. Add a tx-aware sibling `CreateTx(ctx context.Context, q db.Querier, …same params…)` and
   refactor the existing `Create` to delegate: `return r.CreateTx(ctx, r.pool, …)`. Existing
   callers keep working unchanged; `CreateTx` accepts a `pgx.Tx`.
2. In `CreateLedger`, branch the final insert on entry type (replacing the single
   `ledger.go:422` call):
   - **settlement:** `tx := h.pool.Begin(ctx)` → `defer tx.Rollback` (house pattern,
     `ledger_corrections.go:139-144`) → `entry := h.ledgerRepo.CreateTx(ctx, tx, …)` → if
     `targetUserID != userID`, `h.notificationRepo.Insert(ctx, tx, targetUserID,
     models.NotificationPaymentRecorded, payload)` → `tx.Commit`. On any error inside, the
     deferred rollback drops both the ledger row and the notification (atomic).
   - **chore / adjustment:** keep the existing non-tx `h.ledgerRepo.Create(...)` call.
3. Add `notificationRepo *db.NotificationRepo` to the `LedgerHandler` struct and
   `NewLedgerHandler` constructor (**breaking constructor change** — update the wiring at
   `main.go:53` and every `NewLedgerHandler(...)` call in the integration tests; pass
   `notificationRepo` / a fresh `db.NewNotificationRepo(pool)` in tests). This is the only
   cross-file ripple; enumerate the test call sites in the impl (they are in
   `ledger_integration_test.go`, `statement_integration_test.go`,
   `corrections_integration_test.go`, `hygiene_integration_test.go`, and any other
   `NewLedgerHandler` caller — `grep -rn NewLedgerHandler backend/`).

## 5. Migrations — NONE

Confirmed: the `notifications` table (id, user_id, type, payload jsonb, read_at, created_at)
**and** the serving index `idx_notifications_user_created (user_id, created_at DESC)` already
exist from migration **014** (`014_identity_shadow_users.up.sql:22-33`). That index covers
both the keyset list (§1.1) and `MarkAllRead`'s `user_id` filter.

- **`UnreadCount`** and `MarkAllRead` filter `user_id AND read_at IS NULL`. For a family-app
  row count per user this is a handful of rows behind the existing index — a dedicated
  partial index `(user_id) WHERE read_at IS NULL` is **not justified** at this scale and is
  **not** added. State this explicitly in the spec-compliance section of the PR. (If a future
  load profile shows it, that is a separate migration — out of scope here.)

**Do not add a migration in this WP.**

## 7. Acceptance / integration tests (§8: "scoping, unread math, N-3 written on payment")

New file `backend/internal/handlers/notifications_integration_test.go`, all
`//go:build integration` (CI-only — no Docker on the dev host, §9.3). Follow the
`identity_integration_test.go` env harness (`notificationsFor` direct-DB reader, and
**`AddMember(admin, RoleAdmin)` explicitly** — `GroupRepo.Create` does not add the creator,
§9.10 / project memory). For any statement/settlement/backfill setup that backdates rows,
**backdate `group_members.joined_at`**, not just `effective_from` (§9.11 / project memory).

Cases:

1. **Scoping — read.** Seed notifications for users A and B (direct insert). `GET
   /notifications` as A returns only A's rows; B's are never present. Repeat for
   `unread_count` (A's count excludes B's).
2. **Scoping — mark.** A calls `POST /notifications/{B's id}/read` → **404**; B's row stays
   unread (assert via direct DB read). A marking A's own row → `204`.
3. **Idempotent mark-read.** Mark A's row read twice → both `204`; `read_at` unchanged on the
   second call (capture the timestamp, assert equal).
4. **Unread math.** Insert 3 for A → `unread_count == 3`; mark one read → `2`; `read_all` →
   `{updated:2}` and `unread_count == 0`; a second `read_all` → `{updated:0}` (no rows).
5. **Pagination correctness.** Insert N (e.g. 5) notifications for A with distinct
   `created_at`; `GET /notifications?limit=2` returns the 2 newest + a `next_cursor`; follow
   the cursor twice to walk all 5 in strict newest→oldest order with no gaps/dupes; final
   page has `next_cursor == null`. Include a bad-cursor case → `400` and a `limit=0` /
   `limit=101` case → `400`.
6. **N-3 on payment — happy path.** Admin posts `entry_type=settlement` for member M via
   `POST /groups/:id/ledger`. Assert: exactly one new notification for **M** of type
   `payment_recorded`; payload `group_id` matches, `amount == {currency: group.currency,
   value: <posted value>}`. Assert the admin (actor) got **no** N-3.
7. **N-3 self-payment skip.** Admin who is also the payee (settlement `user_id` == admin) →
   **no** `payment_recorded` row for the admin (rule §4.2).
8. **N-3 atomicity / negative.** Confirm N-3 fires **only** for settlement: an
   `entry_type=chore` and an `entry_type=adjustment` post produce **zero** `payment_recorded`
   rows. (Optional, if a fault-injection seam exists: a forced insert failure rolls back the
   ledger row too — otherwise assert the happy-path row+notification both present as the
   atomicity proxy.)
9. **EUR currency case.** One settlement in a EUR group → payload `amount.currency == "EUR"`
   (guards against a hardcoded INR, per D7 / the currency test precedent).

Local gate before pushing impl: `make -C backend test lint`, `go vet` both build tags,
`gofmt` (§9.3). Integration + e2e are the CI gate — never mark done on local green alone.
