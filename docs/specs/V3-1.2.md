# V3-1.2 — Frontend currency (D7)

**Phase 1 · Frontend half of the currency work.** Binding contract:
`docs/master-plan-v3.md` §2 (D7), §3.8, §5 (create-group copy), §8 (V3-1.2 row),
§9.6. Depends on V3-1.1's `openapi.yaml`.

Ships in **one combined PR with V3-1.1** (`docs/notes/phase1-combined-pr.md`).
The `Money` object shape is a breaking change to every amount the FE consumes;
the app is broken until this lands, and e2e is the gate for the combined PR.

## 1. Regenerate types (first, mechanical)

```
cd app && npm run codegen
```

This runs `openapi-typescript ../backend/openapi.yaml -o ./src/api-types.gen.ts`
and produces a `Money` type (`components['schemas']['Money']` =
`{ currency: "EUR"|"USD"|"INR"; value: number }`). `api-types.gen.ts` is
**generated — never hand-edit** (§9.1). Every amount field the BE converted (see
V3-1.1 §3) now types as `Money` (or `Money | null` for the nullable request
fields); `summary_balance`, `balance`, `principal`, `emi_amount`, `outstanding`,
chore/allowance/ledger `amount` are all `Money`. Groups gain a `currency` field.

`app/src/api.ts` re-exports these via `Schemas[...]`; add a
`export type Money = Schemas['Money'];` alias and update the request-helper param
types (`choresApi.create/update`, `allowancesApi.set`, `loansApi.request/approve`,
ledger create) so their `amount`/`principal` params are `Money`, and
`groupsApi.create` takes `{ name; currency }`.

`tsc --noEmit` will now flag **every** call site that reads a money field as a
number or passes a bare number — that compiler error list IS the FE work list.

## 2. `AmountText` + `money.ts` — currency-aware formatting

### Formatting rules (the exact, testable contract)

`money.ts` currently hardcodes `₹` (`formatMinorUnits`) and formats the numeric
part as `NNN.NN` with no grouping (`formatMinor`). Generalize by **currency
symbol**, keep the numeric format **deterministic** so e2e stays green:

| Currency | Symbol | Example (`value=152000`) |
|---|---|---|
| INR | `₹` | `₹1,520.00` |
| EUR | `€` | `€1,520.00` |
| USD | `$` | `$1,520.00` |

Rules:
- **Symbol** prefixes the number, no space.
- **Exactly 2 decimal places**, always (all three currencies are exponent-2).
- **Decimal separator `.`** and **thousands separator `,`** (en grouping) for all
  three currencies. Do **NOT** use `Intl.NumberFormat` — its output varies by the
  CI runner's locale and would flake e2e. Hand-roll the grouping.
- **Sign** semantics unchanged from today's `AmountText`: `credit` → green `+`,
  `debit` → red `−` (U+2212), `neutral` → no sign.

> **Decision / deviation note.** §3.8 gives a cosmetic example `₹1.520,00`
> (European period/comma grouping) for INR. We deliberately use en grouping
> (`₹1,520.00`) for all three currencies: it is deterministic across CI locales,
> keeps existing e2e assertions (`/300\.00/`, `/12\.50/`) passing, and satisfies
> the operative acceptance criterion "formats by currency (₹/€/$, 2 decimals)".
> True per-locale grouping is deferred as a cosmetic follow-up (logged in
> `docs/notes/`), not a Phase-1 requirement.

### API changes to the money helpers

```ts
// money.ts
export type CurrencyCode = 'EUR' | 'USD' | 'INR';
const SYMBOL: Record<CurrencyCode, string> = { EUR: '€', USD: '$', INR: '₹' };

// Unsigned, no symbol, grouped: 152000 -> "1,520.00". Replaces formatMinor's role.
export function formatMinorGrouped(minor: number): string;

// Symbol + grouped, signed: (152000,'INR') -> "₹1,520.00"; (-500,'USD') -> "-$5.00".
export function formatMoney(minor: number, currency: CurrencyCode): string;

// parseMoneyToMinorUnits stays EXACTLY as-is: "12.50" -> 1250. Never parseFloat (§9.6).
```

`AmountText` gains a **required `currency` prop** and drops the hardcoded `₹`:

```ts
interface AmountTextProps {
  minorUnits: number;
  currency: CurrencyCode;   // NEW — no default; caller passes the group currency
  variant?: 'credit' | 'debit' | 'neutral';
  showSign?: boolean;
  size?: 'sm' | 'md' | 'lg' | 'xl';
  style?: TextStyle;
  accessibilityLabel?: string;
}
```

Making `currency` required (no default) forces `tsc` to surface every render site
so none silently keeps `₹`. `allowance-format.ts::describeAllowance` similarly
takes a `currency` and calls `formatMoney`.

**Convenience:** since API money fields are now `Money` objects, add an overload
or sibling `AmountText` usage that accepts a `Money` directly, e.g. callers pass
`<AmountText minorUnits={m.value} currency={m.currency} />`. Prefer reading
`currency` from the `Money` object when one exists; fall back to the group's
`currency` for inputs/derived figures.

## 3. Screens that consume amounts

Every screen that today reads a number now reads `Money.value` and formats with
`Money.currency` (or the group's currency for locally-derived numbers). The
`tsc --noEmit` error list is authoritative; known sites (all under `app/`):

- `app/app/(app)/index.tsx` — dashboard: per-group headline uses
  `group.summary_balance` (now `Money`) **and** `group.currency`; render each
  group's figure in **its own** currency, never summed across groups (D7, §5).
- `app/app/(app)/groups/[id]/index.tsx` — group home balances.
- `app/app/(app)/groups/[id]/chores.tsx` — chore rate (`amount` → `Money`).
- `app/app/(app)/groups/[id]/loans.tsx` — principal / EMI / outstanding.
- `app/app/(app)/groups/[id]/members/[userId].tsx` — passbook / balance.
- `app/src/components/AddEntrySheet.tsx` — parses input with
  `parseMoneyToMinorUnits` (unchanged), then **wraps into a `Money`** using the
  group's currency before POST: `{ currency: group.currency, value: parsed }`.
- `app/src/components/AllowanceSheet.tsx`, `LoanApproveSheet.tsx` — same
  input→Money wrapping on submit; render with `formatMoney`.
- `app/src/components/AllowanceSummary.tsx`, `MemberCard.tsx`, `ListRow.tsx`,
  `MonthHeader.tsx` — pass `currency` through to `AmountText`.

**Currency source:** the group's `currency` comes from `GroupDetail` /
`GroupSummary` (V3-1.1 added it). Thread it down as a prop; do not hardcode and do
not infer from locale. Input sheets read the currency of the group they act on and
stamp it onto the outgoing `Money`.

### No hardcoded `₹` outside `AmountText`/`money.ts`

Acceptance requires **no hardcoded `₹` anywhere except the symbol table in
`money.ts`**. Grep the tree and remove every literal `₹` in screens/components
(they currently exist in `chores.tsx`, `loans.tsx`,
`groups/[id]/index.tsx`, `members/[userId].tsx`, `AllowanceSheet.tsx`,
`LoanApproveSheet.tsx`, `allowance-format.ts`), routing them through the helpers.

`e2e/`:
- **Seed summary consumption:** update `e2e/fixtures/seed.ts` `SeedSummary` type
  to include the second (EUR) group `{id, name, currency}` and its expected
  figure (mirrors V3-1.1 §5's JSON). Update `e2e/support/api.ts` helpers that
  build request bodies (`apiCreateChore` etc.) to send `amount` as a `Money`
  object `{ currency, value }` instead of a bare number.
- **INR assertions:** existing money assertions (`/300\.00/`, `₹` renders) keep
  working with the en-grouping rule; update any that expected a bare number to
  expect the `₹`-prefixed form where the symbol is now shown.
- **One EUR-group assertion (required):** a test that opens the seeded EUR group
  and asserts a `€`-formatted amount renders (e.g. `/€.*\.00/` or the exact
  seeded figure), proving currency flows end-to-end and is **not** the hardcoded
  `₹`. Assert a **state change / concrete text**, never absence-of-failure
  (§9.12). Navigate group tabs by full URL (expo-router web-param gotcha, §9.12).
- **Create-group currency path:** onboarding/create test picks a currency via the
  new picker and asserts the created group renders in that currency.
