**Phase 4, WP V3-4.1** of `docs/master-plan-v3.md`. Contract: §8 row **V3-4.1** +
§5 (platform-adaptive rules). Base: `origin/autopilot/integration` @ `922ec1d`.

**Scope discipline.** FE-ONLY (`app/` + `e2e/`). **No** backend / `openapi.yaml` /
migrations / codegen. **No new features** — this is a structural nav +

## 0. Problem statement (the 2026-07-10 findings)

The current tree nests **two** `Tabs` navigators:

```
app/_layout.tsx                         Stack  (index, (auth), (app), invite)
└─ (app)/_layout.tsx                    Tabs  [screenOptions headerShown:true]   ← OUTER bottom bar + header
   ├─ index.tsx                           Dashboard  (native "Dashboard" header + in-body "Welcome")
   ├─ groups/  (Tabs.Screen href:null)     ← LEAKED lowercase "groups" header (no title set on the hidden route)
   │  └─ groups/_layout.tsx              Stack  (create; [id] headerShown:false)
   │     └─ [id]/_layout.tsx            Tabs  [screenOptions headerShown:true]   ← INNER bottom bar + header  (DOUBLE BAR + DOUBLE HEADER)
   │        ├─ index.tsx                  Overview  (title = group name)
   │        ├─ chores.tsx                 Chores
   │        ├─ loans.tsx                  Loans
   │        └─ members/[userId].tsx       (Tabs.Screen href:null; sets own Stack.Screen title)
   └─ profile.tsx                         Profile  (native "Profile" header)
```

Concrete defects, each traced to a file:
1. **Double bottom bar / clipped labels** — the inner `Tabs` in
   `app/(app)/groups/[id]/_layout.tsx:25` renders a *second* tab bar underneath
   the outer one in `app/(app)/_layout.tsx:22`.
2. **Leaked "groups" header** — `app/(app)/_layout.tsx:32-35` registers the
   `groups` route with `{ href: null }` and **no `title`**; react-navigation
   derives the outer-Tabs header title from the route folder name → lowercase
   **"groups"**, shown above the inner group header.
3. **No responsive column** — every screen is full-bleed `flex:1`; on 1440px web
   the content stretches edge-to-edge (no bounded ~700px column).
4. **No safe-area handling** — `react-native-safe-area-context@~5.6.0` is a
   dependency but **grep finds zero usages** (`SafeAreaProvider`/`useSafeAreaInsets`
   absent); notch/home-indicator insets are unhandled on native.
5. **theme.ts** — has a scale but screens hardcode `fontSize: 24 / 18 / 15`,
   `padding: 16`, `fontWeight: 'bold'` off-scale (e.g. `index.tsx:227`,
   `[id]/index.tsx:357,363`).

## 1. NAV RESTRUCTURE — precise before→after

### 1.1 Target tree (after)

```
app/_layout.tsx                         Stack  (UNCHANGED logic; wrap tree in SafeAreaProvider — see §4.1)
└─ (app)/_layout.tsx                    Tabs  [screenOptions headerShown:false]   ← SINGLE bottom bar (native) / top nav (web); NO tab headers
   ├─ index.tsx                           Dashboard  (in-body header is the one meaningful header)
   ├─ groups/  (Tabs.Screen href:null, headerShown:false)   ← leak killed
   │  └─ groups/_layout.tsx              Stack  (create → "Create Group"; [id] headerShown:false)
   │     └─ [id]/_layout.tsx            Stack  [screenOptions headerShown:true, title = group.name]  ← ONE header
   │        ├─ index.tsx                  Overview  ]
   │        ├─ chores.tsx                 Chores    ]  section switch = <GroupSectionTabs/> segmented control (NOT a navigator)
   │        ├─ loans.tsx                  Loans     ]
   │        └─ members/[userId].tsx       drill-in; own Stack.Screen title ("{name}'s ledger")
   └─ profile.tsx                         Profile  (in-body header added — see §2)
```

The **single bottom bar** is the `(app)` Tabs (Dashboard, Profile). Inside a group,
the three sections are **not** a navigator — they are three sibling **Stack**
routes under one group header, switched by a shared **segmented control**
(`<GroupSectionTabs/>`). This removes the second bar while keeping the URL routes
(`/groups/:id`, `/groups/:id/chores`, `/groups/:id/loans`) intact, so full-URL
navigation and every testID survive.

### 1.2 Files changed for the restructure

| File | Change |
|---|---|
| `app/app/(app)/_layout.tsx` | `Tabs screenOptions={{ headerShown: false }}`. Keep Dashboard + Profile tabs and their icons. Change the hidden `groups` screen options to `{ href: null, headerShown: false }` (kills the leaked "groups" header). |
| `app/app/(app)/groups/[id]/_layout.tsx` | **Convert `Tabs` → `Stack`.** `screenOptions={{ headerShown: true }}`. Set the header **title to `group.name`** for all section routes (keep the existing `useGroup(id)` load + spinner gate). Register `index`, `chores`, `loans` (all title = group name), and `members/[userId]` (headerShown:true; its own screen sets the "{name}'s ledger" title). Remove the per-tab `tabBarIcon`s and the `overviewTitle` admin/member title fork (the "— Overview" suffix goes away; the segmented control shows the section). |
| `app/app/(app)/groups/[id]/index.tsx` | Render `<GroupSectionTabs active="overview" .../>` at the top of both the admin and member views. Demote the in-body `styles.header` (member count + Add member) to a toolbar row **below** the segmented control (it is no longer a title). |
| `app/app/(app)/groups/[id]/chores.tsx` | Render `<GroupSectionTabs active="chores" .../>` at the top of `chores-root`. |

| `app/src/components/GroupSectionTabs.tsx` | **NEW.** Segmented control (see §1.3). Add to `app/src/components/index.ts` barrel. |

### 1.3 `<GroupSectionTabs/>` — the segmented control

- Props: `{ groupId: string; active: 'overview' | 'chores' | 'loans' }`.
- Renders three pressable segments (Overview / Chores / Loans), active one
  highlighted with `theme.color.primary` / `primaryMuted`. One shared component
  for all platforms (segmented control on native, top-nav-style row on web) — no
  `Tabs` navigator, so no second bottom bar.
- **Navigation MUST use absolute URLs that embed the id** —
  `router.replace('/(app)/groups/' + groupId)`,
  `router.replace('/(app)/groups/' + groupId + '/chores')`,
  `router.replace('/(app)/groups/' + groupId + '/loans')`. **Do NOT** use relative
  sibling names or `{ pathname, params:{id} }` named navigation — that reintroduces
  the **expo-router web-param gotcha** (parent `[id]` not populated in the child's
  `useLocalSearchParams` on web; see §9 memory). Use `replace` (not `push`) so
  switching sections doesn't stack history — matches tab semantics.
- Each segment is a touch target **≥44pt** high (§5). Preserve the existing
  full-URL e2e navigation model — `openTab()` in `e2e/support/pages.ts` still
  reaches chores/loans by `page.goto('/groups/'+id+'/'+suffix)`, which keeps
  working because the routes are unchanged.

## 2. HEADER STRATEGY — one meaningful header per screen

**Origin of the leaked title:** `app/(app)/_layout.tsx:32-35` — the hidden
`groups` route has `{ href: null }` but no `title`, so the **outer** Tabs
navigator renders a header captioned by the folder name = **"groups"**. It sits
above the inner group header → two headers.

**Fix:** set `(app)` Tabs `screenOptions={{ headerShown: false }}` and the
`groups` route to `{ href: null, headerShown: false }`. With no tab-level header,
each screen owns exactly one header:

| Screen | The one meaningful header |
|---|---|
| Dashboard (`(app)/index.tsx`) | In-body header row → change "Welcome, {name}!" to a real screen title. Keep it, restyle to `theme.fontSize.xl` (§5). |
| Profile (`(app)/profile.tsx`) | **Add** an in-body title header **"Profile"** (currently relies on the native tab header, which is now off). Same header pattern/style as Dashboard. |
| Group Overview / Chores / Loans (`[id]/*`) | The **`[id]` Stack header, title = `group.name`** (single header for all three sections). Section identity is shown by `<GroupSectionTabs/>`, not a second header. |
| Member detail (`[id]/members/[userId].tsx`) | Its own `Stack.Screen options={{ title: "{name}'s ledger" }}` (already present, line ~196) — unchanged; now correctly attaches to the `[id]` Stack. |
| Create group (`groups/create.tsx`) | The `groups/_layout.tsx` Stack header "Create Group" — unchanged. |

The group `[id]/index.tsx` in-body `styles.header` (member count + Add member /
Invite buttons) is **demoted to a toolbar** under the segmented control — it is a
control strip, not a title, so it does not count as a second header.

## 3. RESPONSIVE WEB — centered ~700px column

### 3.1 Shared wrapper

New component **`app/src/components/ScreenContainer.tsx`** (added to the barrel):

```tsx
// Full-bleed on native; centered, max-width column on web.
import { Platform, View, ViewStyle } from 'react-native';
export const CONTENT_MAX_WIDTH = 700;
export function ScreenContainer({ children, style }: { children; style? }) {
  return <View style={[styles.base, Platform.OS === 'web' ? styles.web : null, style]}>{children}</View>;
}
// base: { flex: 1, width: '100%' }
// web:  { maxWidth: CONTENT_MAX_WIDTH, width: '100%', alignSelf: 'center' }
```

- **Breakpoint approach:** none needed — `maxWidth:700 + width:'100%'` yields
  full width below 700px (390px → full-bleed) and a centered 700px column above it
  (1440px → 700px, `alignSelf:'center'`). This is the intrinsic-max-width idiom;
  no `useWindowDimensions` listener, no media query, so it is SSR/export-safe.
- **Native:** the `web` style is not applied → `flex:1, width:'100%'` full-bleed.

### 3.2 Where it wraps

Wrap it **around each screen's root content view** (not around the navigators —
the bottom bar and header stay full-width; only content is bounded). Screens to
wrap (replace the outermost `<View style={styles.container/screen}>` root, keeping
its `testID`):

- `app/(app)/index.tsx` (Dashboard, `dashboard-root`)
- `app/(app)/profile.tsx` (`profile-root`)
- `app/(app)/groups/create.tsx`
- `app/(app)/groups/[id]/index.tsx` (`group-overview-root`, both admin + member views)
- `app/(app)/groups/[id]/chores.tsx` (`chores-root`)
- `app/(app)/groups/[id]/loans.tsx` (`loans-root`)
- `app/(app)/groups/[id]/members/[userId].tsx` (`member-detail-root`)
- `app/app/invite.tsx`
- `app/(auth)/login.tsx`, `app/(auth)/register.tsx` (inside the KeyboardAvoidingView)

`testID` stays on the same logical root element so selectors are unaffected —
`ScreenContainer` takes an optional `testID` passthrough, OR keep the inner
`<View testID=...>` and wrap it. Keep `FlatList`/`SectionList`/`ScrollView`
**inside** the container so scrolling stays within the bounded column.

## 4. PLATFORM-ADAPTIVE (§5)

### 4.1 Safe-area insets (native)

- Add `SafeAreaProvider` (from `react-native-safe-area-context`) at the **root**,
  wrapping the existing provider tree in `app/_layout.tsx` **without reordering**
  `QueryClientProvider → AuthProvider → ToastProvider → AuthGate → Stack`
  (the `AuthGate` invite-race fix must stay byte-for-byte — §9). Place
  `SafeAreaProvider` as the outermost wrapper.
- The `(app)` Tabs bottom bar + the `[id]` Stack header already consume top/bottom
  insets via react-navigation. The remaining gap is content that sits **outside**
  a header on a full-bleed background — use `useSafeAreaInsets()` for bottom
  padding on the group toolbar / FlatList `contentContainerStyle` where a floating
  action row could collide with the home indicator. Native-only; on web insets are 0.

### 4.2 Keyboard-avoiding forms

Already keyboard-avoiding: `app/(auth)/login.tsx`, `app/(auth)/register.tsx`,
`app/src/components/Sheet.tsx` (covers AddEntry / AddMember / Allowance /
LoanApprove / change-password — all sheet-based forms). **Gap:** the
create-group form `app/(app)/groups/create.tsx` is a bare `View`. Wrap its form
in `KeyboardAvoidingView` with the established `behavior={Platform.OS === 'ios'
? 'padding' : 'height'}` pattern. No other bare-screen forms exist.

### 4.3 Web-only APIs — Platform splits

Current web-only globals (grep across `app/ src/`), all **already inside a
`Platform.OS === 'web'` runtime guard**:

| File:line | API | Guard |
|---|---|---|
| `src/confirm.ts:23` | `window.confirm(message)` | `if (Platform.OS === 'web')` (line 21) |
| `src/storage.ts:9` | branches on `Platform.OS === 'web'` for localStorage vs AsyncStorage | guarded |
| `app/(app)/groups/[id]/index.tsx:97-102` | `Clipboard.setStringAsync` / `navigator.clipboard` path | `if (Platform.OS === 'web')` (line 97); also behind `INVITES_ENABLED` (default OFF) |

**Decision (flagged — §5 wording ambiguity):** §5 says "no web-only APIs outside
`Platform.select`/`.web.tsx` splits". The three sites above use the established,
tested **`Platform.OS === 'web'` runtime guard** (same idiom as `storage.ts`),
which keeps native builds crash-free (the `window`/`navigator` reference is only
evaluated inside the web branch). **Recommendation: keep the runtime guards** and
define the acceptance grep to whitelist lines inside a `Platform.OS === 'web'`
block. Splitting `confirm.ts` into `confirm.ts` + `confirm.web.ts` is the only
change a strict literal reading would force; it is low-value churn and risks
regressing the tested confirm flow (`autoAcceptDialogs` in e2e depends on
`window.confirm` firing a native dialog on web). **If the impl reviewer requires
the literal split**, `src/confirm.ts` is the single file to split (native →
`Alert.alert`, web → `window.confirm`); do not touch `storage.ts` (already a clean
runtime branch with no bare global) or the invite path (dead when flag off). This
is the one UX/impl decision §5 does not settle — impl should pick and note it.

**Acceptance grep** (must pass): every match of
`\b(window|document|localStorage|navigator|location|alert|prompt)\b` in
`app/ src/` (excluding `*.web.tsx`/`*.web.ts`) is inside a `Platform.OS === 'web'`
block. No new unguarded uses introduced by this WP.

## 5. theme.ts — spacing/typography pass (scale, not a redesign)

`app/src/theme.ts` already defines `spacing {xs4 sm8 md12 lg16 xl24}`,
`fontSize {xs13 sm15 md17 lg22 xl28}`, `fontWeight`, `radius`. This WP does **not**
change the scale values — it **applies** them where screens currently hardcode
off-scale numbers, and adds two derived helpers if missing:

- Add a `lineHeight` companion for the type scale (optional, additive) OR leave
  fontSize as-is; **no value churn** to existing tokens (other phases consume them).
- Replace hardcoded literals with tokens in the touched files:
  - `(app)/index.tsx:227` `fontSize:24, fontWeight:'bold'` → `theme.fontSize.xl` +
    `theme.fontWeight.bold`; `sectionTitle:18` → `theme.fontSize.lg`.
  - `[id]/index.tsx` `memberCount:15 / summaryLabel:15 / sectionTitle:15` →
    `theme.fontSize.sm`; `summaryHint:13` → `theme.fontSize.xs`; `padding:16/24`
    → `theme.spacing.lg/xl`.
  - Dashboard/Profile headers → shared header text style using `fontSize.xl` +
    `fontWeight.bold`.

Rule: **no new colors, no scale-value changes** — only substitute literals with
existing tokens in files this WP already edits. If a genuinely new token is needed
(e.g. a `header` text style), add it additively; do not mutate existing entries
consumed by Phases 1-3.

## 9. GOTCHAS / risk call-outs (project memory)

1. **expo-router web-param gotcha** — `GroupSectionTabs` MUST navigate with
   absolute id-bearing URLs (`/(app)/groups/${groupId}/chores`), never relative
   sibling names, or the child's `useLocalSearchParams().id` is empty on web and
   group-scoped queries fetch `/groups//…`. This is exactly why `openTab` uses
   `page.goto` today — mirror that in the segmented control.
2. **AuthGate invite race** — `app/_layout.tsx` `AuthGate` + provider order stay
   byte-for-byte; only add `SafeAreaProvider` as the outer wrapper. Do not move the
   `getPendingInviteToken` redirect logic.
3. **CORS on PUT** — not applicable: this WP adds no API calls / methods; it is
   pure nav/layout. Noted for completeness so impl doesn't introduce a PUT.
4. **Shared component tree** — web e2e is the behavioral gate; do not change
   component *behavior*, only structure/layout. `app/node_modules` may not be
   installed locally — rely on CI's Frontend Web Export + E2E jobs as the true gate.
